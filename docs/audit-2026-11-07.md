## Defects found and fixed in this audit

### Fix 1 (severity: real UB) — dangling `road` pointer in the hook
`g_last.road` pointed into `nav_translate()`'s **stack-local** `turn t;`
struct. `write_nav_info()` runs from the caller *after* `nav_translate()`
returned, with log helpers running at the same stack depth in between: the
road text could read back as garbage (symptom would be nonsense or empty
turn-info strip text at random). Fixed: road text now lives in
`nav_translate.c`'s own persistent storage (`g_road_store[96]`), bounded
and 0-terminated; both the 0x8004 path and the distance-refresh path use
it.

### Fix 2 (severity: build identity) — ambiguous shipped binary
The last v0.4.x hook rebuild had dropped `-DGAL_HOOK_BUILD`, so the
running hook logged `build=unknown`. Rebuilt with the real build id and
shipped: `v0.4.12-audit-20261106`; the hook then self-identifies in the
GEM's Last hook events (grep-verifiable against the shipped binary).

### Fix 3 (severity: hygiene) — two-home payload drift risk
The fork's `mib-mod/sd-payload/…` mirror had drifted from the Addon payload
(several files). A mechanical mirror pass was run (44 files), and
`tools/payload_sync.sh` verifies **no drift** afterwards; its nightly CI
run catches any future divergence.

## Wire-format verification (0x8009 runtime card-clear)

Byte-derivation re-checked in code review, message shape:
`80 09 0a <len> 12 <len> 08 t 10 b 18 l 20 r` = media-sink
`UpdateUiConfigRequest { UiConfig.content_insets = Insets{top,bottom,left,right} }`
per `opencardev-aasdk` (`UpdateUiConfigRequest`, `UiConfig`, `Insets`,
`MediaMessageId = 32777`), matching row data from the owner's GEM presets.
